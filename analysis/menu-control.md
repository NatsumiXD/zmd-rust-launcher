# 输入式菜单、启动日志与游戏关闭快捷键

2026-10-16。最终要求：默认输出启动日志，检查/必要时下载合适的 Games.exe 并启动 Endfield，创建游戏进程后显示输入式菜单；菜单不清屏，启动日志保留在控制台。输入编号后按 Enter 执行。Tab 将初始英文菜单切换为中文，再按一次切回英文。Ctrl+Z 关闭本工具启动的游戏，保留菜单。

## 使用

双击 `D:\Project\zmd\portable\endfield-direct-launch.exe`，确认 Windows UAC 后按默认流程启动。菜单显示游戏 PID 或未运行状态，每 100ms 等待一次输入并检查游戏是否退出，没有空转轮询。

| 按键/选项 | 行为 |
| --- | --- |
| Tab | 中英文切换，保留已输入的文本 |
| Backspace | 删除一个输入字符 |
| 1 + Enter | 检查 Games.exe 更新并启动；已有自有游戏时拒绝重复启动 |
| 2 + Enter | 仅检查/下载 Games.exe；已有自有游戏时提示先关闭 |
| 3 + Enter | 预览，不联网或启动进程 |
| Ctrl+Z | 通过自有进程句柄终止游戏、清理挂起父进程，并保留菜单 |
| 0 或 Q + Enter；Esc / Ctrl+C；关闭窗口 | 只退出可见启动器，游戏继续运行 |
| --menu | 只打开菜单，不自动启动 |
| --launch | 命令行检查/启动/等待，不显示菜单；控制台中同样支持 Ctrl+Z |
| --update-only / --dry-run | 保留原有单次命令行为 |

快捷键在启动器控制台获得键盘焦点时有效，不是系统全局快捷键。Tab 切换菜单界面语言，运行日志固定同时输出中英文；底层错误、路径和参数保留原始内容。所谓“启动后进入菜单”以 CreateProcess 成功为界，不将进程创建成功等同于已经进入游戏主画面。

日志统一按以下四行格式输出：第一、四行为分隔线，第二行为中文，第三行为英文。正常日志写 stdout，错误日志写 stderr，均立即刷新；字段中的换行、制表符及控制字符会转义，不额外增加正文行数。

```text
================
游戏进程已创建，PID：1234
Game process created, PID: 1234
================
```

当前 Rust 工具自动更新的是父进程映像 Games.exe，尚未实现终末地游戏本体的下载/升级。游戏本体更新机制见 [本次逆向报告](endfield-game-update.md)。

更新检查或下载仍按原流程完成后才进入菜单。空输入、无效输入不会执行操作，并提示重新输入。检查更新、预览等操作完成后直接追加下一轮菜单，不需要额外按 Enter 返回；已有日志仍可向上滚动查看。已有游戏自然退出后仍可再次启动。游戏退出前固定其选中的官方映像，防止缓存更新覆盖正在使用的文件。启动日志输出到控制台，不默认生成磁盘日志文件。

## 实现

- `src/main.rs` 仅为带管理员权限 manifest 的程序入口；原参数与下载逻辑移到 `src/lib.rs`，库测试无需管理员权限。
- `src/logging.rs` 统一正常、错误和状态日志格式；中文在前、英文在后，两个正文行不受菜单语言影响，每条日志作为完整块写出。
- `src/menu.rs` 使用 ReadConsoleInputW 和 WaitForSingleObject 读取真实按键，维护最多 32 字符的输入缓冲区和手动回显，Enter 才校验并执行。Tab/Ctrl+Z 保留为即时快捷键；临时关闭系统行输入、回显、Quick Edit、Ctrl+Z 的 EOF 行为，退出时恢复控制台模式。不发送清屏或光标定位转义序列。
- 菜单持有 `Session`，其中包含游戏句柄、挂起父进程与映像固定句柄；轮询子进程退出后释放会话。
- `src/windows.rs` 在互斥锁保护下发布、访问和清除自有进程句柄，避免退出回调与 CloseHandle 竞争。Ctrl+Z 使用自有句柄关闭游戏；退出或关闭 Rust 主窗口不终止游戏。
- 游戏创建后，启动相同 Rust EXE 的内部无窗口守护模式，设置 CREATE_NO_WINDOW，并用 PROC_THREAD_ATTRIBUTE_HANDLE_LIST 只传入父进程、游戏、只读映像和就绪事件四个句柄。守护验证继承句柄、进程身份和文件类型后确认就绪；主进程此时才解除自己对父进程的终止责任。守护独立等待游戏退出，随后清理挂起父进程并退出。不通过 PID 重新打开目标，不修改或恢复官方主线程。
- 可见菜单退出、窗口关闭和单独强制终止可见进程后，后台守护仍持有官方父进程与映像固定句柄。因此后台会保留一个同名 Rust 进程，直到游戏退出。守护及官方父进程仍然属于本工具创建的进程，不读取其他应用的进程句柄。
- Ctrl+Z 使用 TerminateProcess，属于终止进程关闭方式；没有注入、hook 或修改游戏内存。
- 管理员 manifest 继续仅应用于实际启动器二进制。库测试和 process-probe 不要求管理员权限。

## 验证

27 项普通测试通过，包含双语日志四行结构及动态字段换行转义；本轮另行执行的控制台进程探针通过。此前的父进程探针仍保留记录。进程探针仅执行自制 process-probe，不启动官方游戏或启动器。

- 独立隐藏控制台中实际写入并读取 Tab、数字、Enter 和 Ctrl+Z，验证数字必须提交、中文菜单与控制台模式恢复；渲染菜单前写入日志标记，渲染后读回原控制台位置确认日志未被清除。
- 自制游戏进程运行时完整操作菜单：Tab → Ctrl+Z → 0 → Enter；确认菜单保持响应，关闭后会话释放、父进程清理，其他模拟进程不受影响。
- 在独立控制台实际派发 CTRL_C_EVENT，验证关闭回调的句柄清理及随后再次创建会话时取消状态重置。
- 既有父进程探针继续验证指定父 PID/映像、Unicode 参数、挂起主线程不执行、失败清理及只读映像句柄兼容性。
- 记录见 `analysis/menu-control-probe.txt` 和 `analysis/process-probe-result.txt`。

退出行为补充验证：实际向私有隐藏测试控制台发送 WM_CLOSE，另行强制终止测试启动器主进程，两种情况下模拟游戏、父进程和守护均继续运行；随后结束模拟游戏，确认守护清理父进程并退出。菜单输入 0 + Enter 同样验证保留运行会话；Ctrl+Z 的主动关闭路径仍通过。记录见 `launcher-detach-probe.json`、`detach-window-close-test.txt`、`detach-console-probe-test.txt`。所有目标都是工作区自制程序，没有运行官方游戏。

当前改动未启动真实游戏，不冒称新的游戏画面验收；没有修改官方安装文件，没有执行休眠。
