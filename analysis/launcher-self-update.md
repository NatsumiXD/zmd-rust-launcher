# Rust 启动器后台更新（lud）

2026-10-18，0.3.0。每次游戏进程成功创建后，自动请求后台检查 Rust 启动器更新；默认启动、命令 start / restart 和 --launch 均支持。lud 可手动再请求。检查、测速和下载不阻塞命令终端；下载完整并验证后只暂存，必须等当前可见启动器进程退出才替换文件。游戏退出或 Ctrl+Z 关闭游戏本身不触发安装，也不会自动重开启动器。

## 流程与测速

1. 固定读取 NatsumiXD/zmd-rust-launcher 最近 100 个 GitHub Releases，包含预发布、排除草稿。按 pre-v版本-运行ID.尝试次数 选择最高有效发布，不使用排除预发布的 latest 接口。先读官方 API 是为了取得本次真实附件及可信 digest；已有最新版本时结束检查，不下载 EXE。
2. 发现新版后，同时测试 GitHub 官方、https://gh-proxy.org/ 和 https://ghfast.top/ 三条通道。完整传输同一 SHA256SUMS.txt，核对官方 API 提供的大小与 SHA-256；HTML、错误内容或篡改清单不能作为测速成功。记录各通道毫秒数和 KiB/s，按完成时间排序。这里测的是小文件端到端传输，包含 DNS/TLS/延迟，不冒称 EXE 大文件的持续带宽。测速请求采用短超时并限制读取量。
3. 测速结束后才下载新版 EXE，优先最快有效通道；下载失败、大小或哈希错误、PE 文件头不符时，尝试下一条已通过测速的通道。镜像只转发公开附件，不提供版本或校验依据。全通道失败不应用更新。
4. 校验 EXE 的实际大小、SHA-256 和 x64 PE 文件头，写入独立暂存目录并刷新文件。重复检查发现同一已校验暂存版本时复用，不重复下载 EXE。版本、提交、目标路径、新旧 SHA-256、下载通道和备份位置记入 receipt.json。
5. 后台进程持有当前启动器的精确继承进程句柄，等待其退出。即使可见窗口在测速或下载中提前关闭，后台仍会完成剩余工作后应用；不会通过 PID 重开进程，也不会关闭游戏。
6. 应用前重新验证暂存 EXE，取得独占更新锁并确认目标没有被其他更新改变。将旧文件改名为 previous.exe，再将新 EXE 移到原路径；后一步失败时恢复旧文件。后台随后退出，不启动新版窗口或另一个游戏。

GitHub API 字段见 [官方 Releases 文档](https://docs.github.com/en/rest/releases/releases)。镜像前缀规则见 [GH-Proxy 文档](https://gh-proxy.com/docs/github-accelerator)；[GHFast](https://ghfast.top/)也按前缀代理方式参与实测，能否使用以本机本次校验结果为准。测速只覆盖 Rust 启动器附件，官方 Games.exe 的获取流程保持独立。

## 生命周期与日志

后台更新进程是当前可信 Rust EXE 的工作区副本，不执行刚下载的 EXE。只继承当前启动器的查询/等待句柄和就绪事件，使用 CREATE_NO_WINDOW。游戏仍由原有独立守护保留父映像；关闭可见窗口时游戏继续运行。更新进程和父进程守护各自在完成工作后退出，因此窗口关闭后暂时仍可能看到 Rust 后台进程。

每次后续启动游戏、或手动 lud，都向同一后台进程递增检查请求；检查期间到来的请求随后处理。已暂存更新期间终端仍支持 start、restart、status、stop、cn 和补全，原 EXE 路径在当前启动器退出前保持不变。请求失败或下载损坏不影响游戏；已有有效暂存更新在后续网络检查失败时仍保留。

后台将中英文消息写入 events.jsonl，可见终端轮询完整记录并按正常格式只输出英文，cn 回放对应中文。部分 JSON 行会等待写完再读取，显示日志前先清除并恢复当前输入/候选。窗口关闭后的结果继续保存在日志及 state.json 中。

## 边界与保护

自动更新要求主程序名为 endfield-direct-launch.exe。所有辅助文件位于其旁边 launcher-update 中，不写官方安装根目录或已配置游戏目录，不修改注册表、不执行安装器、PowerShell 或注入。仅当目标仍是下载时看到的旧文件才替换，避免覆盖其他实例已完成的更新。旧备份、暂存目录和日志保留，不自动删除仍可能被进程使用的映像。两次重命名间若系统异常中断，可用 receipt.json 指定的 previous.exe 恢复原文件。

HTTPS 使用 WinHTTP，禁用 Cookie 和自动认证，不读取 PAT 或 Git 凭据。首次附件 URL 必须精确属于固定仓库/标签，禁止 HTTPS 跳转到 HTTP，并限制最终域名为 GitHub、已指定 CDN 或镜像站。系统代理失败或 GitHub 限流时会提示并尝试直连。元数据最多 8 MiB，校验清单 64 KiB，EXE 32 MiB；自动更新依据 SHA-256，MD5 只作为发布页附加校验信息。

当前完整性依赖固定 GitHub 仓库、HTTPS、API digest 与发布校验清单，没有独立代码签名密钥。发布 CI 检查 requireAdministrator manifest；下载端不冒称重新完成代码签名验证。build.rs 嵌入版本、源码提交、CI 运行 ID；软件版本和同版本构建都禁止降级。

## 验证

42 项普通测试通过，覆盖版本/预发布排序、防降级、重复或不可信附件拒绝、哈希/清单/PE 校验、暂存时不改目标、复用暂存文件、目标变动拒绝覆盖、替换失败恢复、最快有效通道排序和坏镜像回退。控制台探针、Clippy、release 构建及 GitHub 云端最终结果另行记录。

真实联网关闭后更新探针：官方、GH-Proxy、GHFast 均完成校验文件测速，本次分别约 1150、1186、1389 ms，选择官方通道。下载、校验并暂存公开发布 EXE 后，确认目标与备份均未被替换；结束模拟启动器进程后，确认后台更新完成、备份匹配原文件，另一个加载同一旧映像的模拟进程继续运行。未执行下载的 EXE，未启动真实游戏或官方程序。证据为 lud-after-exit-tests.txt、update-after-exit-probe.json，以及工作区任务 events.jsonl。
